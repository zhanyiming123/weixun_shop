# 角色使用体验手册

> 本文档面向产品、设计和研发团队，描述各角色在"商户管理后台"与"门店管理工作台"中的典型使用场景和操作流程，帮助团队理解每类用户的核心诉求和路径。

---

## 一、角色全景

| 角色 | 所属层级 | 使用系统 | 核心诉求 |
|------|---------|---------|---------|
| 商户管理员（老板） | 商户层 | 商户管理后台 | 掌握全局、管控准入、不陷入细节 |
| 区域管理员（分总） | 区域层 | 商户管理后台 + 门店管理工作台 | 管好辖区门店的运营表现与商品一致性 |
| 事业部商品管理员 | 商户层 | 商户管理后台 + 门店管理工作台（事业部门店） | 维护全公司商品规则，推品给各门店 |
| 事业部优惠管理员 | 商户层 | 商户管理后台 + 门店管理工作台（事业部门店） | 创建并分发全公司统一促销活动 |
| 门店员工（店长/运营/收银） | 门店层 | 门店管理工作台 | 高效处理本店日常商品、订单、营销 |

---

## 二、商户管理员（老板）

### 角色画像

公司老板或商户级管理层，不直接参与门店运营，但需要宏观掌握所有门店的经营状况，并对全公司的规则和准入拥有最终决策权。

### 典型使用场景

**场景一：早上看公司整体经营数据**

```
打开商户管理后台
  → 进入「数据看板」
  → 查看昨日/本周全公司销售额、订单量、退款率
  → 按门店维度下钻，找到表现异常的门店
  → 备注跟进，或转达给对应区域管理员
```

**场景二：新开一家门店**

```
进入「门店管理」
  → 点击「新建门店」
  → 填写门店基础信息（名称、地址、联系人）
  → 分配初始员工账号并设置角色权限
  → 门店即可开始在工作台独立运营
```

**场景三：管理全公司商品分类体系**

```
进入「规则管理」→「商品分类 / 类目管理」
  → 新增或调整类目层级（一级 / 二级 / 三级）
  → 为类目配置属性模板（颜色、规格、材质等）
  → 规则生效后，所有门店创建商品时必须遵从此分类体系
```

**场景四：审批门店自建商品（后期）**

```
收到「审批中心」通知
  → 查看门店提交的商品信息（图片、描述、定价）
  → 确认符合品牌规范 → 审批通过
  → 若不符合 → 驳回并附说明，门店修改后重新提交
```

### 核心体验原则

- 永远不需要进入门店工作台修改具体业务数据
- 数据看板是主入口，5 分钟内完成每日巡检
- 规则变更一次配置，全公司自动生效

## 三、区域管理员（分总）

### 角色画像

负责管理某一区域（如华南区、华东区）下多家门店的运营负责人。可在商户管理后台查看辖区内门店汇总数据，同时在门店管理工作台深入具体门店进行商品和营销操作。

### 典型使用场景

**场景一：查看辖区内各门店本周销售汇总**

```
登录商户管理后台
  → 进入「数据看板」，按辖区/门店维度筛选
  → 查看辖区内各门店的销售额、订单量、退款率
  → 横向比较各门店表现，找到异常门店
  → 切换至门店管理工作台，进入对应门店深入查看明细
```

**场景二：把自己辖区的爆款商品推送给其他门店**

```
切换到商品来源门店身份
  → 进入该商品详情
  → 点击「分享给门店」→ 选择辖区内其他门店
  → 设置哪些字段允许目标门店覆盖（如价格可改、名称不可改）
  → 分享完成，目标门店立即可见该商品
```

**场景三：统一下线某商品（如供应商停货）**

```
切换到源门店身份
  → 进入商品管理 → 找到该商品
  → 将「可售状态」设为「不可售」
  → 所有已引用该商品的门店立即无法销售，无需逐店操作
```

### 核心体验原则

- 商户后台是区域数据的汇总入口，门店工作台是深入操作的执行入口，两个系统互补使用
- 商品分享是核心武器，用于在辖区内快速复制成功商品
- 「不可售」是紧急熔断机制，操作路径要简短

## 四、事业部商品管理员

### 角色画像

公司某事业部的商品负责人，职责是维护全公司通用的商品规则（分类、类目、属性），并通过**本事业部独立创建的门店**来管理和分发标准化商品。每个事业部可以创建自己的专属门店，作为该事业部商品的来源门店，向全公司其他门店推品。

### 典型使用场景

**场景一：维护商品类目体系**

```
进入商户管理后台 → 「规则管理」
  → 调整类目结构（新增 / 删除 / 重命名类目）
  → 为类目补充必要属性（如"服装"类目加入"尺码"属性）
  → 变更实时生效，门店新建商品时看到更新后的类目
```

**场景二：创建品牌标准商品并推给门店**

```
切换至「本事业部门店」身份（门店管理工作台）
  → 进入「商品管理」→ 新建商品
  → 填写标准商品信息（官方名称、品牌图片、标准描述）
  → 设置「门店可覆盖字段」：
      ✅ 价格（允许门店自定义）
      ❌ 商品名称（不允许修改，保持品牌统一）
      ❌ 商品主图（不允许修改）
      ✅ 库存（门店始终自主控制）
  → 保存后「分享给全部门店」或选择指定门店
```

**场景三：商品信息需要统一更新**

```
进入本事业部门店的商品管理
  → 找到需要更新的标准商品
  → 修改官方信息（如更新图片、修正描述）
  → 保存后，所有引用该商品且未覆盖该字段的门店自动同步更新
```

### 核心体验原则

- 每个事业部有自己独立的门店，各事业部的商品库互不干扰
- 字段覆盖权限配置是核心能力，要清晰直观
- 一次推送覆盖全部门店，无需逐店操作

## 五、事业部优惠管理员

### 角色画像

公司某事业部负责全国统一促销活动的运营人员，需要创建跨门店的优惠活动（如全国满减、品牌券），并分发给指定门店执行。与商品管理员类似，优惠管理员同样通过**本事业部独立创建的门店**来发起和分发活动。

### 典型使用场景

**场景一：发起全国节日促销活动**

```
切换至「本事业部门店」身份（门店管理工作台）
  → 进入「营销管理」→ 新建活动
  → 配置活动规则（满减门槛、折扣力度、起止时间）
  → 「分享给门店」→ 选择全部门店或指定区域门店
  → 门店收到活动后，可调整本店的参与方式（如是否叠加其他券）
```

**场景二：查看各门店活动参与情况**

```
进入商户管理后台 → 「数据看板」→ 营销数据
  → 查看各门店在同一活动下的核销量、核销金额
  → 找到参与度低的门店，评估是否需要干预
```

**场景三：紧急暂停某个活动**

```
切换至本事业部门店 → 营销管理
  → 找到活动 → 暂停
  → 所有参与该活动的门店同步暂停（类似商品的「不可售」机制）
```

### 核心体验原则

- 活动从总部下发，各门店可在规则内灵活参与，不可突破上限
- 跨店核销（如顾客在 A 店领券、B 店核销）的规则需后续详细设计
- 活动数据汇总在商户后台可见，门店只看自己的数据

## 六、门店员工

门店员工细分为三个角色：**店长**、**运营**、**收银**。他们的操作范围严格限定在本门店内。

---

### 6.1 店长

#### 角色画像

门店最高权限人员，负责本店日常全面管理，对本店所有数据有完整的读写权限。

#### 典型使用场景

**场景一：接收总部推送的新商品，决定是否在本店上架**

```
登录门店管理工作台 → 「商品管理」
  → 查看「引用商品」列表，看到总部/其他门店新推送的商品
  → 查看商品详情（图片、描述、建议价格）
  → 决定在本店上架 → 设置本店售价 → 上架
  → 或暂不上架，等时机合适再操作
```

**场景二：自建一个本店特色商品**

```
进入「商品管理」→ 新建商品
  → 填写商品信息，选择对应类目（依据总部配置的类目体系）
  → 上传图片、设置价格、填写属性
  → 保存后直接上架（第一期不经过审批）
  → 后续可分享给其他门店引用
```

**场景三：月末查看本店经营数据**

```
进入「数据看板」
  → 查看本月订单量、销售额、退款率
  → 分析热销商品 Top10
  → 根据数据调整下月选品和促销策略
```

---

### 6.2 运营

#### 角色画像

负责本店商品和营销活动的日常运营，重心在选品、定价和活动配置。无法查看订单财务明细。

#### 典型使用场景

**场景一：日常维护商品上下架**

```
进入「商品管理」
  → 筛选「当前上架」商品 → 检查库存、价格是否需要调整
  → 对临近断货的商品及时下架
  → 对新到货商品上架并设置上架价格
```

**场景二：配置本店独立的促销活动**

```
进入「营销管理」→ 新建活动
  → 选择活动类型（满减、折扣、限时特价）
  → 配置参与商品范围、优惠力度、时间段
  → 保存上线，活动在本店即时生效
```

**场景三：覆盖总部分享商品的价格**

```
进入「商品管理」→ 找到某引用商品
  → 查看「可覆盖字段」（价格字段为✅允许覆盖）
  → 输入本店自定义价格 → 保存
  → 本店该商品以新价格展示，不影响总部和其他门店
```

---

### 6.3 收银

#### 角色画像

前台收银人员，核心需求是快速处理订单和售后。收银角色的具体功能权限由管理员在权限配置中决定，不同门店可根据实际业务需要灵活开放或收窄，以下场景为典型默认配置。

#### 典型使用场景

**场景一：处理顾客退款**

```
进入「订单管理」→ 搜索订单号或顾客手机号
  → 查看订单详情 → 点击「申请退款」
  → 选择退款原因、填写退款金额
  → 提交，等待系统处理
```

**场景二：处理退换货**

```
进入「售后管理」→ 找到售后申请
  → 确认退货商品信息 → 点击「确认收货」
  → 系统自动触发退款流程
```

**场景三：查阅当日订单流水**

```
进入「订单管理」
  → 按今日筛选 → 查看订单列表
  → 核对收款金额是否与实际吻合
```

## 七、跨角色协作示例

以下用一个完整的业务链条，展示各角色如何协作配合：

```
① 商户管理员
   └─ 在商户后台配置「零食」类目，添加「保质期」「口味」属性

② 事业部商品管理员
   └─ 在「本事业部门店」新建标准商品「招牌薯片」
   └─ 设置名称/图片不可覆盖，价格可覆盖
   └─ 分享给全部门店

③ 区域管理员（分总）
   └─ 看到新商品推送，通知辖区内门店积极上架

④ 门店运营
   └─ 在工作台看到引用商品「招牌薯片」
   └─ 覆盖本店价格，上架

⑤ 事业部优惠管理员
   └─ 在「本事业部门店」创建全国活动「薯片买二送一」
   └─ 分享给全部门店

⑥ 门店运营
   └─ 看到活动推送，确认本店参与
   └─ 活动在本店生效

⑦ 收银
   └─ 顾客下单后，订单自动应用活动折扣
   └─ 收银处理订单核销

⑧ 商户管理员 / 区域管理员
   └─ 在商户管理后台数据看板查看活动效果（全公司 / 辖区维度）
   └─ 评估是否复制到更多门店或延长活动
```

## 八、权限边界速查

> 收银角色一列为默认配置，实际权限由门店管理员在权限设置中灵活调整。

| 操作 | 商户管理员 | 事业部商品/优惠管理员 | 区域管理员 | 店长 | 运营 | 收银（默认） |
|------|-----------|-------------------|---------|-----|-----|-----|
| 查看全公司/辖区数据汇总 | ✅（全公司） | ❌ | ✅（辖区） | ❌ | ❌ | ❌ |
| 管理商品类目/属性 | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| 新建/编辑门店 | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |
| 审批门店自建商品 | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| 创建标准商品（事业部门店） | ❌ | ✅ | ❌ | ❌ | ❌ | ❌ |
| 商品分享给其他门店 | ❌ | ✅（事业部门店） | ✅（辖区内） | ✅（本店出发） | ❌ | ❌ |
| 本店商品上下架 | ❌ | ❌ | ❌ | ✅ | ✅ | ❌ |
| 本店价格覆盖 | ❌ | ❌ | ❌ | ✅ | ✅ | ❌ |
| 创建本店营销活动 | ❌ | ❌ | ❌ | ✅ | ✅ | ❌ |
| 处理订单/退款 | ❌ | ❌ | ❌ | ✅ | ❌ | ✅ |
| 查看本店数据 | ❌ | ❌ | ✅（切换身份） | ✅ | ✅ | 可配置 |
