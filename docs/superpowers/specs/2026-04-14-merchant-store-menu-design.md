# 商户管理后台门店管理菜单重构设计

## 背景

当前商户管理后台的 `门店管理` 直接对应组织管理页，页面内部通过 `门店` / `区域` 两个 tab 切换不同组织类型。新的导航结构要求把 `门店管理` 改造成一级父菜单，并在其下提供 `门店列表` 二级菜单。同时，商户后台不再需要 `区域` 这部分能力。

## 目标

将商户管理后台的门店入口调整为：

1. 一级菜单 `门店管理`
2. 二级菜单 `门店列表`

并保证 `门店列表` 完全复用当前 `门店管理` 页中 `门店` tab 的查询、列表、新建、编辑基础信息、组织能力等交互。

## 设计范围

本次只调整商户管理后台相关能力：

1. 重组商户端菜单结构。
2. 将商户端组织页固定为 `门店` 视图。
3. 下线商户端 `区域` tab 及其入口。
4. 保留现有门店新建、编辑路由与页面实现。

## 交互设计

### 菜单结构

1. 新增一级菜单 `门店管理`，其本身只承担展开作用。
2. 在一级菜单下新增二级菜单 `门店列表`。
3. 原来的顶层 `门店管理` 直达入口移除，避免重复导航。

### 页面行为

1. 二级菜单 `门店列表` 仍进入现有商户组织管理页。
2. 商户端访问该页时始终固定为 `store` 类型。
3. 页面上不再展示 `区域` tab。
4. 页面上的“新建门店”、列表列、筛选项、分页与操作链接保持现有 `门店` tab 逻辑不变。

### 路由与兼容

1. 列表路由继续使用 `/merchant/organization`。
2. 新建和编辑继续使用 `/merchant/organization/create`、`/merchant/organization/edit`。
3. 页面内部会增加商户端保护逻辑：
   - 如果访问时携带 `?tab=partner`，自动纠正为 `?tab=store`
   - 商户端不再允许通过 UI 切换到 `partner`
4. 新建页和编辑页继续透传 `type=store` 的现有能力；商户端不再暴露 `partner` 的创建入口。

## 实现方式

1. 在 `src/routes.ts` 中将商户端 `merchant/organization` 调整为父级菜单，并在其下挂载 `merchant/organization` 作为 `门店列表` 二级菜单。
2. 在 `src/locale/index.ts` 中补充 `门店列表` 文案，并将父级菜单文案与二级菜单文案区分开。
3. 在组织列表页中增加“商户端固定门店视图”的分支：
   - 解析到商户路径时，默认和兜底类型都固定为 `store`
   - 仅在非商户场景保留 `门店` / `区域` tabs
4. 保持现有 `getOrganizationListPath`、`getOrganizationCreatePath`、`getOrganizationEditPath` 的商户路径复用能力，不新增别名路由。

## 验证方式

1. 在商户管理后台确认左侧菜单展示为 `门店管理 > 门店列表`。
2. 点击 `门店列表` 后，页面默认展示当前 `门店` tab 的内容。
3. 刷新页面或手动访问 `/merchant/organization?tab=partner` 时，仍只会回到门店列表视图。
4. 在门店列表中验证：
   - 查询与重置正常
   - `新建门店` 正常进入创建页
   - `组织能力`、`编辑基础信息` 正常进入编辑页
5. 确认页面中不再出现 `区域` tab。

## 本次不做

1. 不新增新的商户端门店路由别名。
2. 不改动企业端或门店管理系统中的组织/区域能力。
3. 不删除底层 `partner` 数据模型，仅在商户端隐藏并禁止进入。
